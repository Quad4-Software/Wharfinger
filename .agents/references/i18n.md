# i18n: catalogs, resolution, and usage

Zero-dependency. Catalogs are flat TS dicts under
`src/lib/i18n/locales/<lang>.ts`; `en` is the source of truth and the
fallback for every other locale.

## Catalog format

Flat dotted keys, always quoted because of the dots. Values are
strings with `{name}` placeholders.

```ts
export const en = {
	'status.skip': 'Skip to status',
	'status.updated': 'Last updated {time}',
	'cert.expires_one': 'TLS certificate expires in {count} day',
	'cert.expires_other': 'TLS certificate expires in {count} days'
} as const;
```

Other locales declare the same shape partially:

```ts
export const de = {
	'status.skip': 'Zum Status springen'
} satisfies Partial<Record<keyof typeof en, string>>;
```

satisfies rejects keys that do not exist in en, so stale keys fail
typecheck when en changes.

## Using strings

Components import the reactive binding:

```ts
import { t, relativeTime } from '$lib/i18n/locale.svelte';
```

`t('status.updated', { time: relativeTime(at, now) })` re-renders on
locale change because it reads the module $state. fmtDate,
fmtDateTime, and relativeTime are re-exported there with the same
signatures as utils/format minus the locale param; they wrap the
pure functions with the active locale. utils/format itself takes an
optional trailing locale argument.

Server code never touches locale.svelte.ts. It calls
`translate(locals.lang, key, params)` from `$lib/i18n`, because the
module state is process-wide during SSR and only correct inside a
component render.

## Keys and plurals

- Namespaces: `status.*` page chrome, `pill.*`/`overall.*`/`day.*`
  enum labels, `incident.*`, `maint.*`, `weekday.*`, `slo.*`,
  `cert.*`, `latency.*`, `subscribe.*`, `error.*`, `crash.*`,
  `common.*`.
- Plurals: suffix the key with an Intl plural category
  (`_one`, `_other`, `_few`, ...) and pass `{ count: n }`. t() picks
  `key_<category>` via Intl.PluralRules, falls back to `key_other`,
  then the bare key, then en.
- Enum-to-key maps (STATUS_KEYS, OVERALL_KEYS, DAY_KEYS,
  WEEKDAY_KEYS) live in index.ts so call sites keep literal keys and
  the checker sees them.

## Never translate

Config keys and values, log lines, API error codes and JSON error
bodies, identifiers (service ids, slugs, usernames), URLs, the
debug/crash report text, aria roles, CSS class names, and anything
an operator greps for in logs. Translation targets rendered UI text
only.

## Resolution flow

hooks.server.ts computes locals.lang per request:

1. `?lang=` query param, public pages only
2. `wf-lang` cookie (written by setLocale)
3. `[page] locale` in wharfinger.toml (optional)
4. Accept-Language negotiation
5. `en`

Every hop goes through normalizeLocale, which lowercases, maps
regional tags to their base (`de-AT` to `de`), and rejects anything
without a registered catalog. The root +layout.server.ts passes
locals.lang into page data; +layout.svelte calls initLocale during
init, so SSR and hydration render the same locale with no mismatch.
transformPageChunk in the same hook fills `%sveltekit.lang%` and
`%sveltekit.dir%` in app.html; localeDir() returns rtl for known RTL
base tags, ltr otherwise.

Client-side switching: setLocale(lang) updates the state, writes the
cookie and localStorage, and fixes documentElement lang/dir. A
$effect in the root layout calls syncClientLocale() after mount, so
a stored localStorage preference wins over the SSR guess without a
hydration mismatch. There is no user-prefs column, so localStorage
is the admin-side store.

## Adding a locale

1. Copy locales/en.ts to locales/<lang>.ts, change the export name,
   keep the satisfies clause, translate values.
2. Register it in CATALOGS in index.ts.
3. `pnpm check:i18n` reports missing keys (warnings) and keys used in
   code but absent from en (errors, exit 1).
